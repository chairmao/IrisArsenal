# 动画与特效移植

## 源证据优先于主观设计

每招建立“演示片段 → HKX注释/动作轨道 → PayloadInterpreter绑定 → ESP/ESM中的SPEL/MGEF/PROJ/EXPL/ARMO/ARTO/ADDN → NIF几何、NiTransform/NiPSys/材质 → DDS/图集/LUT”的证据链。视频证明外观节奏，绑定证明文件到底有没有被这招调用；不能因为文件同目录、颜色相近或同一个作者就拼接。用户提供的截图也不能单独证明一个NIF的厚度/图层/碰撞半径。

已使用上游：E:/skyrimspecialedition/mods/soulworker_Iris、XP32骨架、0-Elden Rim-Base 3.5.9及相应战技包、SkyrimSE/Data的原版BSA/主文件。具体来源由docs/*source*.json、asset-provenance.json、source-hashes.json逐项登记。外部资源权属独立；本地引用/归档不等于取得Steam再分发授权，未来发布应核实作者许可与依赖安排。

## 角色、武器与骨架

author_moves.py/author_prototype.py使用源HKX/骨架、绑定姿态和真实WEAPON轨道，通过明确坐标变换/比例/握点导出男女skeleton。Kenshi身体、道具轨道与源世界坐标不能混成同一轴；实际效果使用SourcePose与当前origin校正。整体scale、武器length、模型可见长度、FCS起手距离应分别量测。根运动交由原生动画流程，不能另做每帧瞬移追踪目标。

FCS动画名、文件名、内部clip名和男女绑定必须四者一致。曾发生作者生成iris_action_*、FCS却引用iris_*；旧drill文件存在但只有DrillProof也不能算正确。检查文件存在不够，要解析内部名称与帧/骨轨道。普通三连击只取用户批准的三次武器挥击；极致驱动肩持、电脉坐锤分别对照原源动作，不把“用户之前提到坐锤”推到其他招式。

## 离线作者与运行时分工

离线：读取源NIF/DDS/控制器 → 导出真实网格/子网格/透明混合 → 解析粒子出生、寿命、速度/加速度、Emitter变换、SubTex、颜色LUT、尺寸键 → 有限粒子池确定性烘焙 → effects.csv/effect_curves.csv/fx_cues.csv与私有材质/Shader。隐藏MeshEmitter辅助网格仍可能有动画，出生位置需消费，已发粒子不能每帧被拖回发射器。

运行：WarmNext/Borrow/Visual::Create → 本实例Draw(pose,age,opacity,extent) → custom参数/轨道 → ShowParts跟随当前身体/武器，独立Shot/Residue释放后按各自时钟继续 → Return到闲池或Clear。没有Skyrim NiPSys/ENB的完整运行时；程序闪电/折射及未定位ADDN保留限制，不能写“逐像素100%复刻”。

## 颜色、时间与视觉范围

1. SubTex按源归一寿命与帧步/随机起帧/循环解释，不凭经验当FPS。FadeOut=0和FadeOut Percent起点不能相互替换；恢复完整源键，不能把150键截成140或压五点改变爆炸收尾。
2. 源alpha/LUT已包含的衰减不要再乘一次。普通alpha混合的暗billboard会产生明显黑团，不能靠4倍提亮掩盖；用户要求去掉指定两层时只删对应submesh/材质/曲线，不删共享DDS。显示曝光或暗色遮挡修正必须标为移植适配，不假称源参数。
3. 整体加速必须同步出生、寿命、速度、加速度、节点控制器与事件时点；已经烘焙的2倍时钟不能运行时再乘2。爆炸已独立后用游戏秒；地震/电脉是连续动作配套冲击，不因对象独立存在就一刀切改时钟。
4. 范围根据实际网格、alpha/UV/LUT、源粒子亮相、多方向R95等量测；裁剪bounds不是视觉边界。R95是软投影指标，不证明球内逐点覆盖；火星/光晕可以超出伤害球，不应反向无限放大碰撞。
5. 圆环在源旋转时点立即显隐，和钻头共用pose。实机反例及Ogre反汇编证明setIndexDataEndIndex(0)不隐藏；最终用自有SubEntity custom9与专属顶点程序裁剪，不能改共享IndexData或共享材质参数。

## 可执行的验收流程

源文件/事件/引用闭包检查 → 重复导出字节一致 → 骨架/网格/材质/曲线实际读取 → 实际像素/网格CPU多角度动态预览 → 用户新DLL/Ogre实机录像 → 对照源视频逐项修正。CPU预览可以提前发现时序、旋转和几何错误，但不能验证GPU混合、遮挡、ENB或画面最终亮度。

每次查到真实反馈反例，更新证据/不变量，而不是只调主观参数。DLL、Shader和资源表改变跨层合同必须同包；custom9等新初始化不能拿旧DLL搭新Shader。日常Update只验证/组包/复制，PrepareAssets明确属于作者流程，不放进更新脚本。

代码入口：`IrisCombat.cpp:1398`（ShowParts）、`IrisCombat.cpp:215`（Draw）、`IrisCombat.cpp:139`（VisualLayerAge）；作者/量测工具均在tools，完整来源JSON随项目快照保存。
