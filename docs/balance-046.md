## 代码与配置的生效条件

- `IrisCombat.cpp::ConfigureMove` 三远程固定 `bypassDefence=false`；`Flush` 再以 `!RangedMove` 排除远程，避免任何INI值或缓存误设重新启用。
- 三远程不注册防御TLS上下文，不改写 `HIT_SWORD/HIT_MISSED` 为肉体命中。近战共用钩子保留，未迁移 `iShotYou`，未改医疗/部位/护甲入口。
- 项目默认和package配置已更新。游戏 `D:\steam\steamapps\common\Kenshi\mods\IrisArsenal\IrisArsenal.ini` 也已预置本轮指定参数，保留其他个人设置和注释。这样后续UpdateMod的保留策略不会把新权重退回全1。
- **尚未编译、没有部署DLL/模型/材质**。游戏现有旧DLL不能完整执行这些新参数/规则。用户编译 `IrisArsenal.sln → Release|x64 / v100`，正常退出游戏后执行 `UpdateMod.cmd`；新代码合同 `IRIS_RANGED_DEFENCE_TEST_046` 会拒绝旧策略DLL。
- 运行中修改INI不会热更新；今后改个人参数仍需重启游戏。日志总行数不限，专项调试行保持既有频率限制，不恢复轮询。

## 如何核对本次测试

1. 新进程日志前缀应为 `[IrisArsenal 0.4.6]`，有 `IRIS_RANGED_DEFENCE_TEST_046`。
2. 初始化行应显示 `physical_defence_ready ... ranged_override=0`；三招各自 `move_parameters` 应显示 `bypass_block_dodge=0`。
3. `native_hit` 的 `move=5/6/7` 对应火神/脉冲/光炮，`defence=native` 保留原结果。现有前64条单目标调试行用尽后，每次完成的 `damage_result` 仍汇总 `blocked` 和 `missed`。
4. `blocked>0` 表示该事件确实返回了原生 `HIT_SWORD`。单纯没掉血还可能是护甲、未接触或目标状态，不据此认定格挡。`missed` 表示原生未命中结果，需结合动作观察，不能一律叫闪避。
5. 测试目标当时的格挡/闪避状态会影响是否能观察到对应结果；本轮没有强迫敌人进入防御，也没有篡改日志来支持某个结论。
