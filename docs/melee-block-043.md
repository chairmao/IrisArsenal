本轮只处理攻击途中主动转格挡导致的演出中断。用户授权应用于除无特效三连击外的其他近战。C++已修改，未编译、未部署、未实机；资源格式保持042，独立代码合同为 `IRIS_MELEE_BLOCK_043`。

## 实现与证据

只读核对本机游戏PE、KenshiLib导出及RE_Kenshi映射，不把SDK注释RVA当入口。完整原生反汇编、游戏/映射哈希见 `melee-block-043-evidence.json` 中的取证路径。运行代码仍用 `Native(&CombatClass::checkForNeedBlock,...)` 地址式绑定，未使用修饰签名、固定RVA或对象地址偏移。

原生存在两条不同的攻击转防御路径：

1. `CombatClassAI::attackState` 调用 `checkForNeedBlock`。后者满足威胁/时序条件后直接安排 `STARTUP_STATE / BLOCK`。043新增一个钩子，只在六招有效角色/私有技巧/原生动画身份都匹配时于调用前返回false；其他对象/状态原参数调用原函数。
2. 仲裁 `whoAttacksYouOrMe` 可直接写入 `wantsToBlock` 和 `nextMove`；正在真实播放动作时，相关分支只排队防御请求。原生基础 `attackState` 等到当前ImpactPoint的 `motionStopsAnimationFrame` 才允许因格挡意图提前退出。043在六招新建的私有技巧副本中把每一段的此字段设为归一化1.0，保留原 `acceptableEndTime01` 及伤害事件。因此排队意图不再提前取消动作，正常收尾仍由原生决定。没有挂钩仲裁函数或逐帧清旗标。

公共FCS仍是 `anim stop frame 1=99 / num frames=100 / acceptable end time=99.5`。此处1.0是加载后的归一化进度，不是游戏秒数；只在私有副本准备时写一次。无特效三连击与远程副本不修改。未改磁盘FCS、骨架、根轨道、倍率、距离或INI权重。

## 保护窗口与限制

仅当世界初始化完成且不在加载/重置、插件正常、角色有效且实际持有专用武器、未死亡/昏迷/倒地/受击踉跄/戴镣铐、当前近战为六招之一、原生技巧和动画Requirements一致、缓存角色身份匹配，且原生动画进度有限并小于原生结束门时启用。

还必须通过游戏自己的 `stillPlayingAnActionOrSomething`；不依赖可能晚一安全帧才认领的特效 `Actor.active`，也不因已发后效存活而延长保护。使用原生动画层查询，不在AI回调中访问Ogre场景或发射物理查询。已有互斥量只短暂保护本插件缓存；转交原生检查前已释放。

此功能意味着出招期间放弃主动格挡。来袭攻击仍按原生入口计算护甲、伤害和医疗。没有新增受击免疫：钻天破此前的小/大受击反应保护保持，其余招式仍可能因原生受击反应、死亡、昏迷或其他合法取消而中断。不能将本轮称为全招式绝对霸体。

日志启动行包含 `melee_block_guard_ready build=IRIS_MELEE_BLOCK_043`；每个已注册角色仅前三次防御检查跳过记录。`would_block=not_evaluated` 明确说明未调用有副作用的原检查，不能把跳过次数当作实际成功阻止格挡的次数。日志总行数规则和轮询关闭状态不变。
