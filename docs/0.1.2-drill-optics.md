# IrisArsenal 钻头光影与材质修订（0.1.2资源 V1）

2026-10-16完成；用户录像与原日志来自2026-10-15。只修改项目材质/纹理兼容与工具，不编译C++/HLSL、不部署游戏、不修改源模组。

## 直接证据与原因

用户视频640B05约0.2/0.99/4.85/5.62/11.82秒均显示近乎无层次的黑色钻体，约1.79/4.08/7.95秒出现生硬白色光学块。对应日志为IrisArsenal-20261015-212211-803-27532.log，版本0.1.1；19层绑定从StaticObject切到本包材质已成功，问题已不是前一轮绑定遗漏。

kenshi.log明确记录21:29:41 `iris_179f128b96e16ff2.dds Could not be loaded`。该文件是源anim.dds，DDS DX10/BC7格式98，2048×2048；本轮转为同一解码RGBA像素的PNG，原DDS字节保持。

源EXDrill1.nif的15个实体部件没有NiAlphaProperty；能量结构emissive=(1,.484,0)、mult=3，实体metal的glossiness20、镜面强度1或10。旧路径unlit且丢失镜面，发光还除16；使用diffuse alpha作为实体透明度也不符合该源设置。源002.dds本身就是恒定深灰(40,44,49)，离开原镜面/环境光会显得像无形体黑块。

四张源弧光有NiAlphaProperty=4845：SRC_ALPHA/INV_SRC_ALPHA，GREATER阈值8。旧add未乘alpha，源透明区域有222796个亮RGB像素，足以产生不应可见的白边/块。修复按原alpha处理，保留红色/暗色源纹理。

原演示3:57～4:01显示深色机械叶片、冷白移动高光、橙色能量结构与红色旋转弧光。本轮据此恢复源层次，没有添加随意粒子/幕布或改变人物动作。

## 改动与边界

新增金属前向VS/FP，消费既有NORMAL/UV，以Ogre自动矩阵/相机和Kenshi已有太阳/天/地共享参数近似原ENB环境；源光泽/镜面/发光/纹理仍直接读取。高光随真实几何转动和观察方向变化，没有新C++计时或人物控制。

源ENB反射、折射与后处理没有完整移植，不宣称已与滚5渲染完全相同。新HLSL没有执行编译，也没有游戏新画面；真实亮度/色彩与GPU成本仍待测试。

无C++/DLL改动；模型、骨架、几何尺寸、握点、动作、碰撞/伤害、普通武器材质参数及源模组保持。15实体/4光学层没有新增实体或粒子，着色计算增加，不能据此保证FPS不变。

当前观察bin/package/游戏DLL仍为用户0.1.1。本轮材质不新增C++编译需求，但项目上一轮0.1.2尚待编译；先完成IrisArsenal.sln Release|x64/v100，再PreparePackage.cmd，整包同步PNG/program/material/hlsl/CSV。当前package ready=false，未同步游戏。
